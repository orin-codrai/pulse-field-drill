# ADR 0005 — Хранилище чеков (storage backend)

- **Status:** Deferred (решение отложено — таблица `receipts` есть, бэкенд хранилища не выбран)
- **Date:** 2026-05-28
- **Deciders:** @orrin

## Контекст

Схема включает таблицу `receipts` (`backend/app/models/receipt.py`) с полем
`storage_key` и метаданными парсинга. Где физически хранить файлы чеков
(локальный том / S3-совместимое / Telegram file_id) и чем парсить — не решено.

## Статус

**Отложено.** Receipt upload/OCR — не входит в v1.0 (см.
[`../v1.0-plan.md`](../v1.0-plan.md), backlog). Таблица заведена заранее, чтобы
не плодить миграцию позже, но эндпоинты и storage-слой не реализованы.

При возврате к фиче выбрать между:
- **Локальный том** (Caddy `file_server` под `/receipts`, bind-mount) — проще всего
  для соло-VPS, бэкап вместе с `pg_dump`.
- **S3-совместимое** (MinIO sidecar / cloud.ru object storage) — если объём вырастет.
- **Telegram file_id** — не хранить файл вообще, держать ссылку; риск протухания.

## Последствия

- Этот ADR существует, чтобы нумерация ADR была непрерывной и ссылки из плана/журнала
  не были мёртвыми. Будет переведён в Accepted при реализации (Sprint 7+).
