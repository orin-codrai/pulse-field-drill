# Personal preferences

## About me
- Solo developer, systems-level thinker, limited hands-on time (a few hours/week).
- I learn by understanding *why* before *how*. When you fix something, name the
  root cause briefly — not just the diff.
- Optimize for: small reversible steps, shippable end-states at every stop,
  clear commit messages so future-me can pick up cold.

## Communication
- Mirror my language. If I write in Russian, reply in Russian.
- Be concise. Skip "certainly", "of course", and other filler.
- Push back when I'm wrong. Don't agree by default.
- When choosing between options, surface the trade-off, then recommend one.

## Working style
- Use plan mode for non-trivial changes. Show the plan before editing files.
- Don't add comments that restate the code. Comments explain *why*, not *what*.
- Don't write tests "for coverage". Write tests that would have caught a real bug.

## Defaults
- OS: Debian. Shell: bash. Containers: Docker (not Podman unless I ask).
- Git: small focused commits, imperative subject line, no co-author trailers.
- Editor: CLI-friendly; ask before installing anything with a GUI.
